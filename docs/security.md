# Security model

ConvertVault assumes uploaded content is hostile. API object access is owner-scoped and returns 404 for foreign identifiers. Passwords use Argon2; tokens are signed with an operator-managed secret. Upload names are reduced to safe basenames, byte limits are enforced while streaming, checksums are chunked, and storage paths are generated by the server. Originals are never overwritten.

Workers run as an unprivileged user with `no-new-privileges`, a read-only root filesystem, bounded tmpfs, unique temporary directories, subprocess argument arrays, and explicit timeouts. LibreOffice runs headless with a unique profile and macros/scripts are not enabled. Outputs must exist and be non-empty before publication. Document content and tokens must never be logged.

Production operators should use HTTPS, keep infrastructure services on the internal network, rotate all example secrets, restrict outbound worker traffic at the host/firewall layer, run malware scanning before processing untrusted public uploads, install only required fonts, patch images regularly, and test cross-user authorization after upgrades. The current Compose network prevents public ingress to workers but does not itself block worker egress.

Known gaps before exposing an instance to untrusted internet users: TOTP, session revocation, API token scopes, CSRF cookies (the current UI uses bearer tokens), ClamAV integration, archive-bomb inspection, per-IP rate limiting, and a completed external penetration test.
