# Known limitations and fidelity boundaries

ConvertVault is designed to reach Acrobat-class everyday editing and document-suite coverage without making false fidelity claims. The original is preserved, every PDF Studio save creates a revision, and export creates a separate validated derivative.

PDF is a final-layout format rather than a semantic authoring format. PDF Studio detects text blocks, opens a one-click inline paragraph editor at the clicked caret, preserves the detected family/style when reusable, and otherwise selects a same-family installed fallback before using the requested substitution policy. Paragraph edits remove the original operators and rebuild searchable text inside the original region with reflow. Outlined glyphs, unusual encodings, complex shaping, transparency groups, optional-content layers, XFA forms, 3D/video objects, and complex tagged-PDF structures may still be protected or not directly editable. Editing any signed PDF changes its bytes and invalidates prior cryptographic signatures; the current signature tool places a visual signature image, not a new certificate-backed digital signature. Certificate signing, preflight/fixups, automated accessibility remediation, full PDF/UA authoring, print-production separations, and collaborative cloud review are not yet implemented. These are tracked as Acrobat-parity work, not represented as complete.

No OCR system can guarantee 100% accuracy for every scan. Selectable text and structured document XML are extracted directly. Scanned pages and images use local Tesseract/OCRmyPDF when installed; accuracy depends on resolution, skew, noise, handwriting, language packs, typography, and reading order. ConvertVault normalizes Unicode, soft hyphenation, line endings, repeated spaces, paragraphs, and table separators while preserving source wording. It does not silently invent or rewrite uncertain words. Important extracted text should be reviewed against the source.

ConvertVault bundles or installs broad open-source Noto, Liberation, and DejaVu coverage in its containers and can use additional operator-supplied fonts from the internal font directory. It does not redistribute commercial/proprietary font files, and no legal font collection can contain every font ever embedded in a PDF. A missing or non-embeddable family therefore requires a deliberate substitution. PDF-to-DOCX is not currently exposed; any future implementation will be best-effort because PDF does not contain DOCX editing structure. Office fidelity depends on installed fonts; layouts, SmartArt, embedded objects, formulas, presentation effects, and uncommon features may change. Macros are never executed. Pandoc and Office PDF output depend on installed renderers. HEIC HDR may tone-map when written to 8-bit formats. Lossy compression reduces visual quality, password-protected files require the correct password, and compression savings vary with prior optimization.
